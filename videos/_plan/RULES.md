PROJECT: /home/user/cslingo (CSLingo, a Duolingo-style CS study app). We are building short animated explainer videos for the Nature-Inspired Computation course (ECM3412), one per lecture. Square 1080x1080, about 100-115 seconds each, NO narration: the picture does the explaining, with short on-screen captions. Lectures 5 and 6 are already done and are the quality bar: look at them first (videos/lecture-5.html, videos/lecture-6.html, videos/l5/scene-*.js, videos/l6/scene-*.js, videos/out/*-poster.png, and render a few stills). Reference style: calm and clean motion graphics, one idea per scene, one figure that BUILDS UP step by step, short bold headline, tiny labels. CSLingo colour scheme (green/blue/purple/red/orange, Nunito, sticker look).

THE USER'S REQUIREMENTS (follow strictly):
 - EXPLAIN VISUALLY. Every concept is shown with a diagram or animation (things move, swap, grow, light up, connect), never just text on screen. On-screen words are only short labels, tags and the one-sentence caption. If a scene could be replaced by a bullet list, it is wrong.
 - KEEP IT EASY TO UNDERSTAND. One idea per scene, plain words, let each state sit about a second before the next change, do not crowd the stage.
 - CSLingo colour scheme, not any other.

ENGINE (read first): videos/README.md, videos/engine.js (deterministic timeline: V.scene, V.h/V.s element factories, V.place, V.ramp, V.ease, V.flash, V.show, V.type, V.mascot), videos/video.css (canvas 1080x1080, stage 936x640 at (72,262), colour roles .c-green/.c-blue/.c-red/.c-orange/.c-purple/.c-grey, .v-card, .v-gene, .v-tag, .v-text), videos/cards.js (VID.titleCard / VID.recapCard), tools/video-still.js (render stills), tools/render-video.js. A scene is VID.scene({kicker, title:[l1,l2], dur, caps:[[from,to,"caption"],...], build(stage){...; return (t)=>{...}}}); update(t) gets LOCAL seconds and MUST be a pure function of t (no Math.random, Date, timers, rAF, CSS transitions/animations); build the DOM once, update() only sets styles/attributes. Existing helper libraries you may reuse on any page: videos/l5/common.js (window.VID.l5: tourMap, chromosome tiles, badge, tick/cross/arrow/dice pictograms, tour helpers) and videos/l6/common.js + common-2.js (window.VID.l6: tree layout/drawing, plot panel, evaluators). A lecture page lists its scripts in order (see videos/lecture-5.html).
BRAND RULES (from AGENTS.md): sticker look (2-3px border plus a solid lip, box-shadow 0 6px 0 <edge>); NO gradients, glass, soft shadows; text on light uses -ink shades (var(--teal-ink) etc.), text/icons on a saturated fill use -on shades; NEVER white (#fff/white) as colour, fill or stroke (use var(--bg)/var(--panel)); saturated tokens only for fills/lips/icons; symbols (ticks, crosses, arrows, dice, locks) drawn as SVG not glyphs; labels >= 28px; everything inside the stage with >= 12px margin; UK spelling; colour words green/blue/purple/red/orange. Colour roles stay consistent within a video: green = valid/correct/good, red = invalid/wrong/bad, blue = the thing looked at or changed (first parent/main subject), purple = second parent or the operator, orange = missing/attention/chosen, grey = neutral.
NUMBERS MUST BE RIGHT: compute every number, string and result from the real algorithm in code (or verify with node -e) and keep it consistent with the lesson data. Do not invent figures. Respect the course's assessment-integrity rule: examples come from the app's own lessons.
